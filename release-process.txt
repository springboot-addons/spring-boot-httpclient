Release process
===============

Artifacts are published to Maven Central:
https://repo1.maven.org/maven2/io/github/springboot-addons/

References:
- https://central.sonatype.org/publish/release/
- https://maven.apache.org/plugins/maven-gpg-plugin/sign-mojo.html


Branching model
---------------

- develop          integration branch: all changes start and are tested here; never released.
- hc5-sb42         release branch for Spring Boot 4.2.x (2.2.x line).
- hc5-sb41         maintenance branch for Spring Boot 4.1.x (2.1.x line).
- hc5-sb4          maintenance branch for Spring Boot 4.0.x (2.0.x line).
- hc5-sb3          maintenance branch for Spring Boot 3.5.x (1.3.x line).

Promote develop to hc5-sb42 with a merge request (or `git merge --no-ff develop`).
Backport a fix to an older line with a dedicated branch and `git cherry-pick -x <commit>`,
then open a merge request. Never merge develop into an older line.

Run the release from the target release branch, never from develop. After the release, merge the
release commits back into develop so both branches share the next -SNAPSHOT version.


Prerequisites (one-time setup)
------------------------------

1. GPG key

    gpg --list-secret-keys
    gpg --keyserver keys.openpgp.org --send-keys <KEY_ID>

2. GPG passphrase (permanent Windows user variable, then restart the terminal)

    setx MAVEN_GPG_PASSPHRASE "your-passphrase"

   maven-gpg-plugin 3.2.8 reads this variable automatically (recommended practice).
   No export of JDK_JAVA_OPTIONS is needed: the required --add-opens flags are in .mvn/jvm.config.

3. Maven Central credentials in %USERPROFILE%\.m2\settings.xml, server id "central".

4. Git: the current branch must track origin (the release plugin pushes commits and tags).

    git push -u origin <branch>

5. Docker must be running (the release runs `clean verify`, and the tests use Testcontainers).


Release (one command)
---------------------

From the release branch (example for the 4.2 line):

    git switch hc5-sb42
    git pull --ff-only
    .\mvnw.cmd release:prepare release:perform

or, with a Maven installation instead of the wrapper:

    mvn release:prepare release:perform

The POM configuration:
- maven-release-plugin activates the "release-sign-artifacts" profile during perform,
  pushes commits/tags automatically, uses a local checkout and runs `clean verify` before tagging.
- maven-gpg-plugin signs artifacts (verify phase) using MAVEN_GPG_PASSPHRASE.
- central-publishing-maven-plugin uploads and publishes automatically (waitUntil=published).

What happens:
1. release:prepare updates versions, runs the tests, commits, tags (e.g.
   spring-boot-starter-httpclient5-parent-2.1.2), pushes, then bumps to the next SNAPSHOT and pushes.
2. release:perform builds the tag, signs the artifacts and deploys them to Maven Central.

If something fails:
- during prepare: `.\mvnw.cmd release:rollback`, then clean up any tag/commit left behind.
- during perform: the tag is already pushed; re-run `.\mvnw.cmd release:perform` (or restart from the tag).

Do not commit: release.properties, pom.xml.releaseBackup, pom.xml.tag, pom.xml.next.


Notes
-----

- Target Java is 17; the build works with JDK 17 up to JDK 25.
- `target/checkout` from a previous perform contains read-only Git objects: remove it with
  `cmd /c "rmdir /s /q target"` before a clean build if Maven cannot delete it.
